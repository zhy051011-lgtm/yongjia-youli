## 一句话介绍

把永嘉文化资料、游客的时间与兴趣，整理成能够调整、查证和带走的旅行手册。网页和原生微信小程序共用同一套规划与 AI 工具服务。

## 作品要解决什么问题

游客经常需要在零散介绍中自行选择目的地、组合行程，并再次确认开放和体验条件。本项目将需求输入、资料查阅、时间分配和调整收在一个流程中。这里描述的是产品问题假设，尚未开展用户调查或效果评估。

首版聚焦永嘉文化旅行，收录芙蓉古村、苍坡古村、丽水街、瓯窑小镇、茗岙梯田、黄南林坑六条文化资源。公开报道提供文化背景；当天开放、费用和活动需要再向运营方确认。没有将历史活动包装为可实时预约的商品。

## 用户实际怎样使用

1. 从古村慢行、工艺寻访、田野观察进入，或直接填写出行需求。
2. 选择日期、首站时间、同行人群、兴趣、时长、片区与交通。
3. 系统筛选同片区资源，分配建议停留与用户指定的转场缓冲，生成时间轴。
4. 临时缩短时间、减少步行、选择雨天备选或移除点位，行程重新计算，并列出变化。
5. 阅读文化线索、产品策划的探索任务及公开来源；出发前核验开放条件。
6. 网页导出 Markdown 或打印，小程序复制旅行手册；配置 DeepSeek 后可用自然语言查询和调整。

## 智能体与确定性计算的分工

DeepSeek 负责理解自然语言、选择工具、组织回答。`find_resources` 检索资料，`build_itinerary` 校验需求和计算行程，`get_weather` 请求真实预报。前端显示这些工具的操作摘要。时间预算、资源对象和页面更新由代码完成；不是依赖模型输出一段看似合理的时间表。

未配置密钥时仍能使用规则规划，AI 对话明确提示配置缺失。已配置密钥并验证 `deepseek-flash` 模型工具调用成功（资料检索、行程重算、天气查询三个工具均已通过实际 API 调用验证）。

## 设计与本版改进

- 以旅行手册为核心：发现、行程和文化手册三条清晰入口，桌面与手机自适应。
- 使用米白、山林绿与陶土色、原创山水插画，建立与地方文化相关的视觉表达。
- 每站绑定来源、建议停留、探索任务和待核验事项，保留信息边界。
- 调整操作改变真实结构化行程，可反复操作；两端共用规则，减少行为不一致。
- 原生小程序使用 WXML/WXSS 页面与后端请求，不需要将网页套在 web-view 中。

## 商业验证路线（计划，非已取得成果）

先验证游客是否愿意使用并完成一次真实出行，再与景区、研学机构、文创或工艺体验商户核对供给。后续可探索机构服务、研学线路策划、经明确授权的商户推荐等方式。首版没有付费订单、合作商家、营收、用户量或转化率，材料不得虚构这些数字。

建议现场试用记录：用户是否完成规划、调整是否解决问题、哪些资料需要现场更新、真实转场是否超过缓冲。这些记录需要今后实际采集，不能用本地自动化测试替代。
